# ADR-0005: Scene Format Principles — Versioned JSON, Inputs Only

- **Status:** Accepted
- **Date:** 2026-07-19 (Session 1)
- **Detailed by:** M1 (`02-SCENE-FORMAT.md`, JSON Schema, TypeScript interfaces)

## Context

Scenes are the platform's core asset: saved, shared via URL, remixed, generated by procgen and AI, and replayed deterministically for leaderboards. The format outlives every other component, so its principles must be fixed before anything is built on top of it.

## Decision — binding principles

1. **Inputs, never results.** A scene stores object types, transforms, physical properties, world settings (gravity/plane angle), and the seed. Never positions-over-time, never computed metrics. The simulation is the only producer of results.
2. **JSON, human-inspectable, compact by design.** Short but readable property names, defaults omitted (schema defines defaults), numbers quantized to sensible precision (e.g., positions to 0.1 mm) to keep files small and diffs stable.
3. **Integer `schemaVersion` + forward-only migrations.** Every scene records its `schemaVersion`. The `scene-format` package ships pure migration functions `v(n) → v(n+1)`; loading always migrates forward to current. Old scenes never break. There are no backward migrations.
4. **`engineVersion` recorded, determinism scoped to it.** Same scene + same seed + same `engineVersion` ⇒ identical simulation. Across engine versions, no promise — leaderboards and replay verification are keyed by engine version.
5. **One validation gate for every producer.** Human builder, procgen, AI generation, and API upload all pass the identical schema + semantic validation (`scene-format`, shared client/server per ADR-0004). AI output gets an additional auto-repair pass *before* the gate, not a looser gate.
6. **Tolerant reader, strict writer.** Readers preserve unknown fields where safe (forward compatibility); writers emit only schema-defined fields at the current version.
7. **Scenes are data, never code.** No embedded scripts or expressions. Any future "custom logic" objects require their own ADR and sandbox design.
8. **Identity and lineage live outside the document.** `scene_id`, author, timestamps, `remixed_from`, like counts, etc. are backend metadata — the scene document itself stays portable (export/import, URL-encoded sharing of small scenes remains possible).

## Sketch (illustrative only — normative schema comes in M1)

```json
{
  "schemaVersion": 1,
  "engineVersion": "0.1.0",
  "meta": { "title": "Marble spiral", "durationHint": 60 },
  "world": { "gravity": [0, -9.81], "planeAngle": 0, "seed": 421337 },
  "objects": [
    { "id": "o1", "type": "domino", "pos": [0.0, 1.0], "rot": 0.05 },
    { "id": "o2", "type": "marble", "pos": [1.2, 3.0], "props": { "r": 0.04, "density": 2.0 } }
  ]
}
```

## Consequences

- Remix, procgen, and AI features all reduce to "produce a valid scene document" — one contract to test against.
- Migration functions are mandatory maintenance with every schema change; CI runs a corpus of historical scenes through migration + validation to guarantee "old scenes never break."
- Quantization rules must be part of the determinism spec (M2): serialize → deserialize must reproduce bit-identical simulation inputs.

## Alternatives considered

- **Binary format (FlatBuffers/CBOR):** smaller and faster, but kills human inspectability, URL-sharing, easy AI generation, and diff-based remix tooling. Compression (gzip/brotli in transit and at rest) captures most size wins. Revisit only if R6 materializes.
- **Storing simulation results for playback:** would make playback trivial and cheating trivial too; contradicts determinism-as-source-of-truth and bloats storage. Rejected.
- **Semver string for schema:** migrations need a total order and single dimension; an integer is exactly that.
